## 二、根因（2026-11-24 07:00 已确认）

诊断日志（11-24 07:00）：

```
[指标] 已选金额=¥ 120.00元
[指标] 提交面板={'boxes': 1, 'btn': 'btn disab', 'termsChecked': False, 'termsDisabled': False}
提交按钮/预约须知未就绪（terms-unchecked）…
```

`termsDisabled=False`、`termsChecked=False`，`prepareSubmit` 仍返回 `terms-unchecked`
——只有一种可能：**传进去的 `confirmTerms` 是 false**。

查代码：抢票主流程调用 `_book_candidate(...)` 时**没有传 `confirm_terms=True`**，
默认 False 一路传到 `bb.submit(timeout, false)` → `prepareSubmit(false)`：
看到须知未勾选就直接返回 `terms-unchecked`，根本不点。

H1（页面 disabled）、H2（选错面板）、H3（选场没生效）全部被推翻。

修复：`ticket_grabbing_pipeline` 的 `_book_candidate` 补上 `confirm_terms=True`。

## 七、刷新能不能优化（待验证的优化项）

现状：放场时目标日期不在日期栏，`focus_date` 用 `driver.refresh()` 整页刷新（约 358ms）；
刷新后 SPA 要重新初始化，这是 `terms-unchecked` 的温床。

可选的优化（按收益排序，都还没实现）：

1. **不刷新，改用页面自己的日期刷新**：日期栏由 Vue 组件渲染，尝试找到刷新日期列表的方法
   （`getReserveDate` 只能切表格，刷新后表格没渲染出来，暂不可用）。收益：省 ~350ms + 免初始化。
2. **刷新与接口探测并行**：探测到放场的同时就发起刷新，刷新完成前先用接口数据准备候选，
   刷新后只做「点日期页签 + 选场」。收益：省 ~200ms。
3. **用接口候选替代 DOM 解析**：`day/info` 已经返回 `venueSiteId/spaceName/startDate`，
   可以直接得到候选，读表只用于让表格渲染出来。收益：省 ~150-200ms。
4. **提交就绪等待降到 1.2s**（已实现）：正常路径立即返回；未就绪时最多等 1.2s，
   再按 0.25/0.5s 重试两次，之后换下一个候选——总预算约 2s，不拖慢抢票。

## 八、方案 B：不整页刷新，让日期栏出现新日期（实验，默认关闭）

### 实现

`QueryManager.refresh_date_bar(day)`：找到页面的场馆组件，调用它自己的
`init()` / `getReserveDate()` 让它按服务端最新的 `advanceReservationDays` 重建日期栏；
轮询等待目标日期出现在日期栏（最多 2s）。成功则继续点页签，**不 reload 页面**，
预解的验证码 token 不会被销毁。

开关：`config.yaml` 里加 `runtime.patch_date_bar: true`（默认 false = 只走方案 A）。
`focus_date` 里顺序是：目标日期在栏里 → 直接用；不在 → 若开关打开先试 B；
B 失败才整页刷新（A）。B 成功但随后点页签拿不到数据时，会标记失败并回退刷新。

### 验证指标（明天放场时看这几行）

| # | 日志 | 期望 |
| --- | --- | --- |
| 1 | `[指标] 日期栏(T-60s)= {"tabs":[...],"advance":2,...}` | 放场前只有 D0/D+1 |
| 2 | `[指标] 日期栏(放场后)= {"tabs":[...],"advance":3,...}` | advance 变成 3 |
| 3 | `[指标] 日期栏patch：{"ok":true,"called":["init",...]}，目标出现=true，耗时=??ms` | 出现=true |
| 4 | `日期栏已通过状态刷新出现（未整页刷新）` | 出现该行 = B 生效，未 reload |
| 5 | `日期窗口刷新结束 … 耗时=…` | **不应出现**（出现说明回退了 A） |
| 6 | `预解验证结果完整且有效` 在放场后仍可用 | B 成功时预解 token 应仍有效 |
| 7 | `[指标] 放场→开始提交=…ms` | 目标 ≤ 700ms（比 A 少 ~220ms 刷新） |
| 8 | `下单成功` / `tradeNo` | 有订单 |

### 验证步骤

1. 放场前一天把 `runtime.patch_date_bar: true` 加到 `config.yaml`；
2. 06:45 重启控制台（保证加载最新代码），06:55 点「开始抢票」；
3. 07:01 抓日志：`grep -E "\[指标\]|日期栏|patch|下单成功|平台回执" logs/console-runtime.log`；
4. 判定：
   - 出现 `目标出现=true` + `未整页刷新` + 下单成功 → **B 可用**，以后默认开；
   - `目标出现=false` → B 不可用，保持 A（日志里会看到回退到 `日期窗口刷新结束`）；
   - B 成功但点页签失败（出现 `patch 后没拿到数据，回退整页刷新`）→ B 不可用，保持 A。
